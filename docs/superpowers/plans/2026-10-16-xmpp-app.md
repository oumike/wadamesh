# XMPP Chat App + Relay Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A Store Lua app (`xmpp`) that chats over the owner's XMPP account (1:1 + MUC) through a self-hosted plain-HTTP relay that holds the XMPP session.

**Architecture:** A one-file Python relay (`scripts/xmpp-relay/xmpp_relay.py`) keeps a slixmpp session, stores a 50-message window per conversation in SQLite, and serves one sealed `POST /w` endpoint. The Lua app polls it every 5 s while open, using a seal built from `wada.crypto.hmac_sha256` (HMAC-CTR + encrypt-then-MAC). The wire format is tab-separated lines.

**Tech Stack:** Python 3.11+, slixmpp 1.8.5, sqlite3/asyncio/hashlib from the stdlib; Lua 5.4.7 (`LUA_32BITS`) on the wadamesh `wada.*` API; the host harness in `scripts/lua-harness`.

**Spec:** `docs/superpowers/specs/2026-10-16-xmpp-app-design.md`

## Global Constraints

- Relay is one file; its only third-party dependency is `slixmpp==1.8.5`, imported lazily so the pure parts import without it.
- Keys: `PBKDF2-HMAC-SHA256(passphrase, salt = "wada-xmpp-v1", 2000 rounds, 64 bytes)`; `enc_key` = bytes 1..32, `mac_key` = bytes 33..64.
- Sealed message: `nonce(16) | ciphertext | tag(16)`; keystream block `HMAC(enc_key, nonce | u32be(block))`, block from 0; `tag = HMAC(mac_key, dir | nonce | ciphertext)[1..16]`; `dir` = `"Q"` request, `"P"` reply.
- Request: `S <sid> <q> <cursor>`, then `M <conv> <cmid> <text>` and `R <conv> <seq>` lines. Reply: `P <q>` first, optional `E xmpp-offline`, `C`, `G`, `A` lines, `N <cursor> <more>` last. Tab-separated, `\n`-terminated.
- Escaping in text fields: `\` → `\\`, TAB → `\t`, LF → `\n` (CR dropped).
- Reply plaintext ≤ 6000 bytes. Outgoing text ≤ 1000 bytes (cut on a UTF-8 boundary).
- Seal failure → HTTP `200`, body exactly `DENIED`. Never `403` (`wada.net` collapses non-2xx to `-1`).
- History: 50 messages per conversation (configurable `history`). Initial sync: ≤ 10 newest per conversation, round-robin, never paged.
- Poll every 5000 ms while open; after 6 consecutive failures back off to 30000 ms; immediate re-sync when `more = 1`.
- `wada.store` writes only on setup, on app open (`qb` reservation), every 1000 requests, and on a user send/ack. Never per sync.
- App RAM bounds: 50 messages per conversation, 40 conversations.
- SD log: `c<conv>.log`, rotate to `c<conv>.old` at 30 KB, flush at most every 2000 ms; offered only when `caps.sd and caps.sdk_ext`.
- Every Lua callback stays under 100,000 instructions; the harness `cost` scenario fails above 25,000 per tick.
- Nothing in either side hard-codes `sumat.org`, donut, or a port beyond the `listen` default `0.0.0.0:8765`.

## Review Focus

- **Relay database lost or replaced** (device cursor ahead of relay revision): the app must notice `N` < its cursor, clear its view and resync from 0, not sit silently empty. Test in Task 6.
- **Own messages echoed back** (room reflection of a device send, carbons, MAM backfill overlapping live delivery): exactly one copy in history. Test in Task 2/Task 3.
- **Text at the edges**: tabs, newlines, backslashes, emoji, and a >1000-byte paste cut mid-UTF-8 sequence must round-trip or be cut cleanly. Test in Task 2 and Task 5.
- **Sends pending when the app closes**: resent exactly once on next open. Test in Task 6.
- **Empty account** (no roster, no bookmarks): list shows an explanatory empty state, not a blank screen or an error. Test in Task 7.

### Task 8: Optional SD history

**Files:**
- Modify: `deploy/apps/xmpp/1.0/xmpp.lua`
- Modify: `scripts/lua-harness/harness.lua` (scenario `xmpp_sdlog`)

**Interfaces:**
- Consumes: Task 6 message ingest, Task 7 chat view.
